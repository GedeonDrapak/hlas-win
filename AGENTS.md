# Agent guide - Hlas for Windows

Push-to-talk dictation for Windows, the twin of
[Hlas for macOS](https://github.com/GedeonDrapak/hlas). Rust, no webview.
Read `docs/HANDOFF.md` first for the current state and what still needs a real
Windows PC.

## Layout

```
src/core/   platform-independent, unit-tested on any OS (`cargo test`)
src/win/    everything that touches Windows (cfg(windows) only)
shared/     text rules generated from the macOS Swift sources - never hand-edit
assets/     icon, tray icons, onboarding panels (tools/render_assets.py)
installer/  NSIS script
tests/fixtures/czech-48k.wav   6 s of Czech speech for end-to-end checks
```

| File | Concern |
|---|---|
| `core/audio.rs` | padding (0.25 s lead-in, 1.2 s minimum, silence gate), downmix, resampling, level |
| `core/text.rs` | hallucination filter, replacements, priming prompts, Smart text request/validation |
| `core/press.rs` | hold vs quick-tap latch state machine |
| `core/config.rs` | settings JSON, 0.1.0 migration, data folder |
| `core/history.rs` | last 50 results, retention, search |
| `core/decode.rs` | audio file import via symphonia |
| `core/model.rs` | model presence, SHA-256, legacy move |
| `win/coordinator.rs` | the dictation brain: sessions, cancel, pipeline, delivery |
| `win/hotkey.rs` | WH_KEYBOARD_LL hook: push-to-talk edges, chord cancel, Esc |
| `win/mic.rs` | cpal/WASAPI capture, warm stream, device choice, test-file mode |
| `win/inject.rs` + `clipboard.rs` | target check, full-format clipboard snapshot, Ctrl+V |
| `win/overlay.rs` | the status pill (layered GDI window, per-monitor DPI) |
| `win/engine/*` | local whisper (load, prefetch, idle unload), cloud, Smart text, model download |
| `win/ui/*` | native-windows-gui windows on one UI thread: settings, history, result, onboarding |
| `win/tray.rs` | tray icon and menu, owns the main thread |

## Build and check

On Windows: `cargo build --release` (needs LLVM for bindgen and CMake).

On a Mac, a full cross-build catches every type error in the Windows layer in
about a minute (needs `brew install mingw-w64`):

```bash
MW=/opt/homebrew/opt/mingw-w64/toolchain-x86_64
export BINDGEN_EXTRA_CLANG_ARGS_x86_64_pc_windows_gnu="--target=x86_64-w64-mingw32 -I$MW/x86_64-w64-mingw32/include -I$MW/lib/gcc/x86_64-w64-mingw32/16.2.0/include"
cargo clippy --release --target x86_64-pc-windows-gnu -- -D warnings
cargo test            # core, runs natively on the Mac
```

CI (`.github/workflows/windows.yml`) is the real Windows check: clippy, tests,
installer, a local Czech transcription, screenshots of every window and a
hotkey-to-Notepad run. Download the `qa-screenshots` artifact to see the UI.

## QA hooks (like `HLAS_STEP` on macOS)

| Env var | Effect |
|---|---|
| `HLAS_STEP=0..3` | opens the welcome tour at that step |
| `HLAS_SHOW=settings\|history\|result\|pill-recording\|pill-transcribing\|pill-error` | opens one surface |
| `HLAS_FAKE_AUDIO=<file>` | the "microphone" returns this file, so the whole pipeline runs without one |

Command line: `hlas.exe --transcribe <file> [--out f] [--engine local|groq|openai] [--language cs] [--smart]`,
`hlas.exe --download-model`, `hlas.exe --version`.

Logs: `%LOCALAPPDATA%\Hlas\debug.log` (rotates at 1 MB). Never log transcript
text or keys.

## Rules

- **Shared text rules come from macOS.** Smart text prompt, priming prompts and
  the hallucination list live in `shared/hlas-shared.json`, generated by
  `python3 tools/shared_from_mac.py ../hlas`. CI fails on drift. Change the
  Swift sources first, then regenerate.
- Keep the core free of Windows APIs so it stays testable everywhere.
- No webview, no new heavy dependencies; the small exe is a feature.
- Never long dashes in user-facing text (owner's rule). Hyphens only.
- Push-to-talk keys must be harmless when they also reach the focused app;
  Hlas never swallows them (only Esc while a dictation is active).

## Gotchas

1. `keyring` needs the `windows-native` feature, or it silently uses an
   in-memory mock and nothing persists.
2. rubato's FFT resampler has an output delay; feed it in chunks and flush
   (see `core::audio::resample` and its test) or the tail is lost.
3. Windows removes a low-level hook that stalls; the hook thread only forwards
   events and re-installs the hook every 10 minutes.
4. `SendInput` cannot reach elevated windows from a normal process and fails
   silently; `inject.rs` detects elevated targets and shows the text instead.
5. nwg windows are built once on the UI thread and hidden on close; other
   threads use `ui::send`, never nwg directly.
6. The release exe is a GUI-subsystem app: PowerShell does not wait for it
   unless you use `Start-Process -Wait`, and console output needs
   `AttachConsole` (done in `cli.rs`); prefer `--out`.
